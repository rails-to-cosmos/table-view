Design notes, proposals, and reviews for =table-view=.  All documents here are
Org-mode and cross-link each other (see [[file:../CLAUDE.md][CLAUDE.md]] for the convention).  Start
here and follow the links.

* Deliveries

table-view is one renderer against one [[file:../SCHEMA.md][contract]], delivered several ways.  A
[[file:../CONTEXT.md::*Producer][producer]] owns the rows and picks a delivery; the [[file:../CONTEXT.md::*Vector][parity vectors]] keep the
implementations answering alike.

- *Emacs* — =table-view.el= (repo root, package convention).  Shipped.
- *Web* — =web/table-view.js=, dependency-free, no build.  Shipped; design:
  [[file:web-renderer.org][web-renderer.org]].
- *Native-window* — the web renderer in a WebKitGTK window, for GUI with no
  browser.  Spiked; design: [[file:native-window.org][native-window.org]].
- *Term* — a brick/vty console TUI, a second renderer against the same
  contract, for terminals and headless boots.  Spiked; design: [[file:term.org][term.org]].

Consumers read one generated surface, =dist/<delivery>/= (=make dist=,
gitignored): the authored single-file renderers (=.el=, =.js=) are copied in
beside the built binaries (=table-view-window=, =table-view-term=), so a
producer points at one directory per delivery and never at the build tree.  The
=.el= at root and =web/table-view.js= stay the canonical sources — =dist/=
holds copies, never a second edited home.

* Design notes (shipped)

Design records for features already in the package.

- [[file:proposals/nulls-ordering.org][Nulls-first / nulls-last ordering]] :: place empty cells at the top
  or the bottom of a sort, independent of direction; the four-stage =^= cycle
  and the =(COL . DIRECTION-CODE)= encoding.  Shipped in =table-view.el=; the
  browser renderer spells the same idea as the =direction= strings
  =asc-nulls-first= / =desc-nulls-first= (see [[file:../SCHEMA.md][SCHEMA.md]]).
- [[file:proposals/native-accelerator.org][Native accelerator (tvx)]] :: a Rust background process as a fast
  local =page-fn= over =jsonrpc.el= for 100k–1M rows.  Shipped as
  =table-view-native.el= plus the =tvx= crate in =native/tvx=; the document
  is kept under =proposals/= as the design record.  Its ERT suite
  (=table-view-native-test.el=) skips the binary-dependent tests where =tvx=
  has not been built.
- [[file:web-renderer.org][Web renderer (table-view.js) — design rationale]] :: the "why" behind the
  browser renderer's palette/contrast values, column geometry, filter grammar,
  suggestion tiers, and interaction hazards.  The source points here rather
  than carrying the essays.

* Bugs

Concrete defects to fix, each with the fix sketched.

None open.

** Fixed

- *Mark/unmark moves point to column 0 (loses cell column, walks off last row).*
  ~table-view-mark-toggle~ and ~table-view-unmark~ both ended with a raw
  ~(forward-line 1)~, which dropped to column 0 (no cell-snap) and, on the last
  data row, left the rows region onto the hint/blank line.  *Fixed:* both now
  end with ~(table-view--move-row 1)~, the module's own row mover (preserves the
  column, snaps to a cell, clamps at the last row).  Regression tests:
  ~tv-test-mark-move-preserves-column~, ~tv-test-mark-last-row-stays-on-row~,
  ~tv-test-unmark-last-row-stays-on-row~.  Surfaced from org-glance table use.
